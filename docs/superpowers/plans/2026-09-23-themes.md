# Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let each person pick a theme on their own phone, shipping a dark Halloween theme that swaps both the palette and the app's glyph from a heart to a pumpkin.

**Architecture:** `src/theme.css` stays the single source of truth for every colour — the default palette on `:root`, each alternative in a `[data-theme="…"]` block that overrides the same custom properties at runtime. `scripts/check-contrast.mjs` *parses that CSS file* rather than duplicating hexes, so a new theme is automatically under the contrast gate and the two can never drift. TypeScript holds only theme ids, display names and glyph grids — never colours. The picker's swatches get their colours by putting `data-theme` on the swatch element itself.

**Tech Stack:** React 19, Vite, Tailwind v4 (`@theme` tokens), TypeScript, `node --test` (built in, no dependency), oxlint.

## Global Constraints

Copied verbatim from `CLAUDE.md`; every task inherits these.

- 3px ink borders, hard offset shadows with **no blur**, `steps()` easing only, `border-radius: 0`.
- Hot pink is fills and borders only — it fails contrast as text. **Everything must pass WCAG AA.**
- Mobile-only, 375px primary. Touch targets ≥44px. Inputs ≥16px or iOS zooms and won't zoom back.
- Emoji, not custom pixel art, for categories and weather.
- Google's map colours stay untouched.
- Dates are `yyyy-MM-dd` strings. A date happening *today* is not past — use `<`, not `<=`.
- No hooks after an early return. Run `npm run lint` before committing.
- The in-app browser **cannot composite**: CSS transitions freeze mid-flight, `requestAnimationFrame` never fires, Google Maps tiles never paint. Verify logic and computed styles, never appearance. Neutralise the `boot-in` animation with `document.querySelector('.device').style.animation='none'` before measuring, or every box reads ~3% small.

```js
import { readFileSync } from 'node:fs'
import { fileURLToPath } from 'node:url'
import { dirname, join } from 'node:path'

const CSS = join(dirname(fileURLToPath(import.meta.url)), '..', 'src', 'theme.css')

/**
 * The CSS is the single source of truth for colour. Parsing it here means a
 * new theme is under this gate the moment it exists, and the script can never
 * disagree with what actually ships.
 *
 * Returns { pink: {ink:'#1a1033',…}, halloween: {…} } — `pink` is whatever is
 * declared in `@theme`, each other key a `[data-theme="…"]` block.
 */
function readThemes(cssPath = CSS) {
  const css = readFileSync(cssPath, 'utf8')
  const tokens = (block) =>
    Object.fromEntries(
      [...block.matchAll(/--color-([a-z-]+)\s*:\s*(#[0-9a-fA-F]{6})/g)].map((m) => [m[1], m[2]]),
    )

  const base = css.match(/@theme\s*\{([\s\S]*?)\n\}/)
  if (!base) throw new Error(`no @theme block found in ${cssPath}`)
  const themes = { pink: tokens(base[1]) }

  for (const m of css.matchAll(/\[data-theme=["']([a-z-]+)["']\]\s*\{([\s\S]*?)\n\s*\}/g)) {
    themes[m[1]] = { ...themes.pink, ...tokens(m[2]) }
  }
  return themes
}

const T = readThemes().pink
```

```ts
/**
 * Which themes exist, and which one this browser is using.
 *
 * Colours are deliberately NOT here. `src/theme.css` owns every value, so the
 * stylesheet and the contrast gate can never disagree; this module carries
 * only what CSS cannot express — ids, display names, and the pixel grid each
 * theme draws its glyph from.
 */

export type ThemeId = 'pink'

export type Theme = {
  id: ThemeId
  name: string
  /** Rows of a pixel grid; 'X' is filled. Must be rectangular. */
  glyph: string[]
}

/** The heart every other glyph replaces. */
export const HEART = [
  '.XX...XX.',
  'XXXXXXXXX',
  'XXXXXXXXX',
  'XXXXXXXXX',
  '.XXXXXXX.',
  '..XXXXX..',
  '...XXX...',
  '....X....',
]

export const THEMES: Theme[] = [{ id: 'pink', name: 'pink', glyph: HEART }]

export const DEFAULT_THEME: ThemeId = 'pink'
export const STORAGE_KEY = 'dateideas:theme'

export function isThemeId(v: unknown): v is ThemeId {
  return typeof v === 'string' && THEMES.some((t) => t.id === v)
}

/** Anything unreadable, unknown or hostile resolves to the default. */
type Storageish = Pick<Storage, 'getItem' | 'setItem'>

export function readTheme(store?: Storageish): ThemeId {
  try {
    const s = store ?? globalThis.localStorage
    const raw = s?.getItem(STORAGE_KEY)
    return isThemeId(raw) ? raw : DEFAULT_THEME
  } catch {
    // Private mode throws on access. A theme is a nicety, not a requirement.
    return DEFAULT_THEME
  }
}

export function writeTheme(id: ThemeId, store?: Storageish): void {
  try {
    const s = store ?? globalThis.localStorage
    s?.setItem(STORAGE_KEY, id)
  } catch {
    // Same. The choice simply will not survive a reload.
  }
}

export const glyphFor = (id: ThemeId): string[] =>
  (THEMES.find((t) => t.id === id) ?? THEMES[0]).glyph
```

```ts
import { useCallback, useEffect, useState } from 'react'
import { readTheme, writeTheme, DEFAULT_THEME, type ThemeId } from './themes'

/**
 * The active theme. `index.html` has already stamped `data-theme` before
 * paint; this re-asserts it from the validated value, which also corrects an
 * unknown id left behind by an older build.
 */
export function useTheme() {
  const [theme, setThemeState] = useState<ThemeId>(() => readTheme())

  useEffect(() => {
    const root = document.documentElement
    if (theme === DEFAULT_THEME) root.removeAttribute('data-theme')
    else root.setAttribute('data-theme', theme)
  }, [theme])

  const setTheme = useCallback((id: ThemeId) => {
    setThemeState(id)
    writeTheme(id)
  }, [])

  return { theme, setTheme }
}
```

/* ── Halloween ──────────────────────────────────────────────────────────
   Dark. `line` and `text` go bone so they read on a dark ground, and the
   hard offset shadow becomes pumpkin — on near-black, a darker shadow does
   nothing, so it glows instead.

   `deep` is LIGHTER than `hot` here. That is not a mistake: "hot is fills

   vivid accent passes and a dark sibling is what fails, so `deep` keeps its
   ROLE — the sibling that is safe as text — and changes its lightness. */

  --color-paper: #120a20;
  --color-card: #241539;
  --color-line: #f2e9dc;
  --color-text: #f2e9dc;

- [ ] **Step 1: Write the rasteriser**

The calendar markers render at **8px**. A shape that looks right at 96px can lose its defining feature entirely at 8. Create `scripts/check-glyph.mjs`:

```js
/**
 * Rasterises a glyph at the sizes the app actually renders and prints the
 * pixels, so shape decisions rest on evidence rather than on how it looks
 * blown up. An 11-wide heart once looked roundest at 96px and rasterised
 * identically to the old one at 8px — rounder where it did not matter.
 *
 *   node scripts/check-glyph.mjs PUMPKIN
 */
import { THEMES, HEART } from '../src/lib/themes.ts'

const GRIDS = { HEART, ...Object.fromEntries(THEMES.map((t) => [t.id.toUpperCase(), t.glyph])) }
const name = process.argv[2] ?? 'HEART'
const grid = GRIDS[name]
if (!grid) {
  console.error(`unknown glyph ${name}; try one of ${Object.keys(GRIDS).join(', ')}`)
  process.exit(1)
}

const W = grid[0].length
const H = grid.length
for (const size of [8, 11, 14, 24]) {
  const h = Math.round((size / W) * H)
  console.log(`\n  ${name} at ${size}px (${size}x${h})`)
  for (let y = 0; y < h; y++) {
    let row = ''
    for (let x = 0; x < size; x++) {
      // Nearest-neighbour, which is what shape-rendering:crispEdges approximates.
      const gx = Math.min(W - 1, Math.floor((x * W) / size))
      const gy = Math.min(H - 1, Math.floor((y * H) / h))
      row += grid[gy][gx] === 'X' ? '#' : '.'
    }
    console.log('  ' + row)
  }
}
```
